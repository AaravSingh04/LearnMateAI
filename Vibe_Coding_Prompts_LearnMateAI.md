## How to use this file

Each numbered step is one prompt block. Open the `LearnMateAI_Project` folder in Google Antigravity. Copy **only one numbered prompt at a time** into the Antigravity agent chat. Let the agent finish, run the application, check the result, and then continue to the next step. Do not paste all prompts together.

Keep this file open beside Antigravity. If something is wrong, describe what you actually see (for example, “The new subject appears until I refresh the page, then disappears”) instead of guessing at the cause. Ask the agent to explain any file or function you do not understand.

The first version is a local classroom project, not a production service. Do not add login, payments, cloud deployment, mobile apps, or unrelated features in this version.

## Product to build

Build **LearnMate AI**, a multi-subject learning web app for a student. The home dashboard must allow the user to add, open, rename, and delete subjects. Each subject has its own separate learning space. Inside a subject, the user can upload PDF or PPTX class material, view previous uploads, and generate a study pack containing a summary, key concepts, revision notes, practice questions, and a quiz from the uploaded material.

The app must save subjects, uploads, study packs, and quiz attempts in SQLite so they remain after a server restart. Every item must stay connected to its subject; content from one subject must never appear in another subject by mistake.

### Important AI rule

Use the current official Google GenAI Python SDK (`google-genai`) from the backend only. Read the current official Google AI for Developers documentation if needed. Read the API key from the `GEMINI_API_KEY` environment variable and the model name from `GEMINI_MODEL`. Never expose the key in frontend JavaScript, HTML, browser responses, or source control. If no key is configured, show a clear setup message and keep the rest of the app usable. Never pretend that a mock or hard-coded study pack was generated by AI.

## Step 1 — Database schema

```text
Implement SQLite setup in backend/database.py. Create the local database at data/learnmate.db and enable SQLite foreign-key enforcement.

Create these tables with appropriate primary keys, foreign keys, timestamps, and constraints:

1. subjects: id, name (required), description (optional), created_at, updated_at. Subject names should be trimmed and must not be empty.
2. materials: id, subject_id, original_filename, stored_filename, file_type, uploaded_at, extracted_text, processing_status. Each material belongs to exactly one subject.
3. study_packs: id, material_id (unique, one current study pack per material), summary, key_concepts_json, revision_notes, generated_at, model_name.
4. quiz_questions: id, material_id, question_text, options_json, correct_option_index, explanation. Each question belongs to one uploaded material.
5. quiz_attempts: id, material_id, score, total_questions, attempted_at.

Use SQLite transactions where appropriate. Make sure deleting a subject safely removes its related database records. File cleanup should be handled safely by application logic, not by storing files inside the database. Provide a reusable get_db_connection() helper and a database initialization function.

Run the initialization code and confirm that the database and all five tables are created. Do not invent subject or study material seed data; a new installation can start with an empty dashboard.
```

## Step 3 — Subject and material APIs

```text
In backend/main.py, create the FastAPI application and these API endpoints. Keep the request and response shapes consistent with backend/models.py.

Subjects:
- GET /api/subjects — return all subjects, ordered by name.
- POST /api/subjects — create a subject; reject an empty name and a duplicate name with a clear 400 or 409 response.
- GET /api/subjects/{subject_id} — return one subject or 404.
- PATCH /api/subjects/{subject_id} — rename or update the description; validate input.
- DELETE /api/subjects/{subject_id} — delete the subject and its related records after server-side checks and safely remove its uploaded files.

Materials:
- POST /api/subjects/{subject_id}/materials — upload a PDF or PPTX for that subject, save the file under data/uploads, extract its text, save the material record, and return the material metadata. Return 404 if the subject does not exist.
- GET /api/subjects/{subject_id}/materials — list that subject's uploads, newest first.
- GET /api/materials/{material_id} — return material details including processing status, but do not return the full extracted text unless specifically needed by the internal study-pack flow.
- DELETE /api/materials/{material_id} — delete the material and all related study-pack, question, and quiz-attempt records, and safely remove its stored file.

Add clear server-side validation, sensible HTTP status codes, and readable errors. Never trust only frontend validation. Enable local development CORS only if it is needed; preferably serve the frontend from the same FastAPI app. Mount the frontend files after defining API routes so static routes do not shadow /api routes. Confirm that the FastAPI app starts without errors and that /docs lists the routes.
```

## Step 5 — Generate and save study packs

```text
Add these endpoints in backend/main.py:

- POST /api/materials/{material_id}/generate-study-pack — find the material and its extracted text, call ai_service.py, validate the result, then save or replace that material's study pack and its quiz questions in SQLite. Return the saved study pack. Return 404 if the material does not exist, 400 if no text was extracted, and a clear service error if AI is not configured or fails.
- GET /api/materials/{material_id}/study-pack — return the saved study pack and its questions, or 404 if one has not been generated yet.
- POST /api/materials/{material_id}/quiz-attempts — accept selected answers, calculate the score on the server using stored correct answers, save the attempt, and return the score plus explanations. Never trust a score sent by the browser.

Ensure that every endpoint checks the material and subject relationships. Keep stored JSON parseable and validate all generated question fields. Add the new routes to the automatic API docs and verify their success and error responses where possible.
```
